# C Variable Research — เจ้าใหญ่จะกลับมาแข่งไหม (Participation)

**วันที่:** 2026-06-13
**คำถาม:** ควรเอาเรตดุของ "เจ้าใหญ่" มาทับเรตสนามไหม → เขาจะมายื่นงานนี้แค่ไหน (ค่า C)
**ข้อจำกัดใหญ่:** winner_history มีแค่ **ผู้ชนะ** → วัดได้แค่ "ความถี่/recency การ*ชนะ*" เป็น proxy ของ participation (undercount คนยื่นแล้วแพ้)
**สคริปต์:** `scripts/_research_c_participation.py`

---

## 1. ผลจากข้อมูลจริง (ถนนแข่งขัน, 3,679 win, 1,018 คู่บริษัท-อำเภอ)

### Recency — P(กลับมาชนะในอำเภอเดิม ภายใน g ปี | ชนะปีนี้)
| g | P | |
|---|---|---|
| 1 ปี | 33% | กระโดดแรงช่วงแรก |
| 2 ปี | 48% | |
| 3 ปี | 53% | เริ่ม plateau |
| 5 ปี | 59% | ~40% ไม่กลับมาเลย (one-and-done) |

### Frequency — สัญญาณที่แรงที่สุด (P recur ภายใน 2 ปี)
| ประเภท | P | |
|---|---|---|
| ขาจร (เคยชนะ 1-2 ปี) | **13%** | แทบไม่กลับ |
| ประจำ (3-4 ปี) | 58% | |
| **เจ้าถิ่น (≥5 ปี)** | **90%** | เกือบแน่ |

→ **ความถี่ (เจ้าถิ่นแค่ไหน) ทำนาย C ได้ดีกว่า recency มาก** — เจ้าถิ่น ≥5 → 90% · ขาจร → 13%

## 2. ⚠️ บทเรียนสำคัญ: C-จาก-win "ยังไม่พอ" จะ drive overlay

เคสมงคลธรรม-บุ่งคล้า: ชนะปี [2561,62,63,67,68] = เจ้าถิ่น, ล่าสุด 2568 → **C(อำเภอ) ≈ 90%**

แต่ **เขาไม่มายื่นงานหนองเดิ่นจริง!** → ถ้าใช้ C-จาก-win อย่างเดียว จะบอก "มงคลธรรมน่าจะมา (90%)" → ทับ 40% → คาด 1.2M = **ผิด** (จริง 1.33M)

**ทำไม C-จาก-win พลาด:**
- วัดได้แค่ "แอคทีฟในอำเภอไหม" (กว้าง) — ไม่ใช่ "จะยื่นงาน*นี้*ไหม" (เจาะ)
- มงคลธรรมแอคทีฟบุ่งคล้าจริง แต่**ขยับไปงานใหญ่ 3-6M** (งานนี้ 2M ไม่ตรงไซซ์เขาแล้ว) + ระดับตำบลหนองเดิ่นเขาถอยตั้งแต่ 2563

→ C ที่แม่นต้องมี: **budget-fit + participation ระดับตำบล + ความถี่การ*ยื่น* (ต้อง all-bidders)**

## 3. สรุป + คำแนะนำ
- ✅ **Frequency เป็นแกนหลักของ C** (เจ้าถิ่น→สูง, ขาจร→ต่ำ) · recency เสริม (decay 2 ปีแรกชัด)
- ✅ C-v1-จาก-win **ใช้ได้แค่กรอง "ผีจริง"** (เจ้าที่หายไป 5+ ปี เช่น เค.อี.ซี.) — น้ำหนักจางเอง
- ❌ **C-v1 ยังไม่ปลอดภัยพอจะ drive overlay เอง** — จะ over-predict participation (เคสมงคลธรรม) → **ต้องรอ all-bidders + budget-fit ก่อน implement C**
- 🎯 **นัยต่อ staging:** fix หนองเดิ่นจริง = **Z-blend (แยกเจ้าใหญ่→ตำบลว่าง→อำเภอ)** ไม่ใช่ C · C เป็น refinement รอ data

## ข้อจำกัด
- win-only (ไม่เห็นคนยื่นแล้วแพ้) → participation undercount
- ไม่มี budget-fit / job-level features → แยก "ขยับไปงานใหญ่" ไม่ได้
- ต้องการ all-bidders pipeline เป็น foundation (ดู spec §4)
