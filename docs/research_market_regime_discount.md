# ผลวิจัย: ตัวขับ %ส่วนลดจริง = "ระบอบตลาด/หน่วยงาน" ไม่ใช่ budget/ชั้นผู้รับเหมา

**วันที่:** 2026-06-11
**แหล่งข้อมูล:** `winner_history.db` (617K งาน) + `getProcureResult` API (sample 144 งาน, จำนวนผู้ยื่นจริง)
**ต้นเรื่อง:** กัญจน์ทักว่า "ไม่เชื่อว่างานถนน 48% ไม่แข่ง เพราะถนนแข่งดุที่สุด" → debug แล้วเจอว่าวิเคราะห์เดิมปน 2 ตลาด
**สมมติฐานกัญจน์:** core คือ "ช่วงราคา → ระดับชั้นผู้รับเหมา 6 ชั้น → ข้อจำกัดการรับงาน" → ตรวจสอบ

---

## 1) ราก: "ถนน" ปนสองตลาดคนละระบอบ
| ตลาด | n | ไม่แข่ง (ลด<5%) | median ลด |
|---|---:|---:|---:|
| กรมทางหลวง/ทางหลวงชนบท | 1,530 | 80% | 0.3% |
| ท้องถิ่น (อบต./เทศบาล/อบจ.) | 2,264 | 29% | **26.1%** |

ตัวเลข "48% ไม่แข่ง" เดิม = ปนงานกรมทางหลวง (รายใหญ่ประมูลชิดเพดาน). ตลาดจริงของกัญจน์ = ถนน คสล. ท้องถิ่น **median ลด 30%** (แข่งดุที่สุดในทุกหมวด — ตรงกับ domain knowledge).

## 2) budget ไม่ใช่ตัวขับ (คุม budget แล้วเทียบตลาด)
| budget | ท้องถิ่น median | กรมทางหลวง median |
|---|---:|---:|
| <1 ลบ. | 25.0% | 0.5% |
| 1-2 | 27.4% | 0.2% |
| 2-5 | 27.1% | 0.4% |
| 5-15 | 24.7% | 0.3% |

คุม budget เท่ากัน → ท้องถิ่น ~25% / DOH ~0.4% **ทุกช่วงราคา**. งาน DOH เล็ก <1 ลบ. ก็ยังชิดเพดาน 93% → ถ้า budget เป็นเหตุ งานเล็กต้องแข่งดุ แต่ไม่. **"งานใหญ่ลดน้อย" ในข้อมูลรวม = Simpson's paradox** (งานใหญ่ = DOH ครองตลาด).

## 3) จำนวนผู้ยื่นจริง (getProcureResult, n=144) — หักล้างทฤษฎีชั้น
| budget (ท้องถิ่น) | n | ผู้ยื่น median | ลด median |
|---|---:|---:|---:|
| 0.5-1 ลบ. | 22 | 3 | 26% |
| 1-2 | 22 | 5 | 21% |
| 2-3 | 20 | 6 | 31% |
| 3-5 | 22 | 6 | 32% |
| 5-7 | 17 | 5 | 21% |
| 7-10 | 17 | 6 | 6% (bimodal) |
| **กรมทางหลวง** | 24 | **2** | **0.1-0.4%** |

- **corr(budget, จำนวนผู้ยื่น) = +0.00** ในตลาดท้องถิ่น → ขนาดงานไม่ลดจำนวนคู่แข่งเลย
- บางงานท้องถิ่นมีผู้ยื่น **30, 38, 46 ราย** (ตลาดเปิดสุด)
- **จำนวนคู่แข่งไม่ขับส่วนลด**: ท้องถิ่น 2 ราย → ลด 28% / DOH 2 ราย → ลด 0% (เท่ากันแต่ตรงข้าม)
- DOH = 2 รายคงที่ทุกขนาด + ไม่กดราคากัน → pool เล็ก (ชั้นบีบจริง) + ระบอบราคาแน่น

## 4) nuance: งานท้องถิ่น 7-10 ลบ. เริ่ม bimodal
8/17 งานลด <5% (แม้ผู้ยื่น 6-16 ราย) — น่าจะเป็นงาน **อบจ. ขนาดใหญ่** ที่พฤติกรรมเริ่มเหมือน DOH → "ระบอบตลาด" ซ้อนที่ระดับราคาสูง (อบจ. vs อบต./เทศบาล) ไม่ใช่ขนาดเพียวๆ.

## 5) ข้อสรุป (ตัวขับ %ส่วนลด)
| ตัวขับที่สงสัย | ผล |
|---|---|
| ขนาดงาน/budget | ❌ ไม่ขับ (ส่วนลด+จำนวนผู้ยื่นไม่ลดตามขนาด) |
| จำนวนคู่แข่ง | ❌ ไม่ขับ (2 ราย ท้องถิ่น 28% vs DOH 0%) |
| ชั้นผู้รับเหมา | ⚠️ แค่สร้าง pool เล็กของ DOH ไม่ใช่ gradient ในตลาดท้องถิ่น |
| **ระบอบตลาด/หน่วยงาน** | ✅ **ตัวขับเดียวที่จริง** (ท้องถิ่นแข่งดุ / DOH ชิดเพดาน) |

## 6) สิ่งที่จะแก้ระบบทำนายราคา
**A (หลัก):** classifier `agency_market(dept)` → `local` (อบต./เทศบาล/อบจ.) vs `central` (กรม/ทางหลวง) → กรอง reference pool ให้ตรงระบอบเดียวกัน. ทำให้แม่นโดยออกแบบ (ตอนนี้รอดเพราะ contested floor ≥15 บังเอิญตัด DOH ทิ้ง — เปราะ).

**B (รอง):** contested floor ต่อหมวด (ถนน ~15-20, อาคาร/water_struct ~5) — ต่อจาก water_struct ที่ทำแล้ว.

**ไม่ทำ (evidence ปฏิเสธ):** budget, จำนวนคู่แข่ง, ชั้นผู้รับเหมา = ไม่เพิ่มเป็นมิติทำนาย.

**Followup:** อบจ. vs อบต./เทศบาล อาจเป็น sub-regime ที่ระดับราคาสูง (>7 ลบ.) — ดูเพิ่มถ้ากัญจน์ขยับไปงานใหญ่.

**Raw:** `data/bidder_count_expanded.json` (144 งาน + จำนวนผู้ยื่น), `data/bidder_count_pilot.json`. สคริปต์ `scripts/_probe_bidder_count_pilot.py` (throttled, safe).

## 7) ตรวจสอบทฤษฎีชั้นผู้รับเหมา (กัญจน์ 2026-06-11, รอบลึก)

กัญจน์ให้ศึกษาระบบชั้น 6 ระดับ (ขอบเขตมูลค่า: ชั้น6 <10ลบ, ชั้น5 10-50, ชั้น4 50-100, ชั้น3 100-300, ชั้น2 300-500, ชั้น1 >500, + ชั้นพิเศษ ไม่จำกัด).

**จิ๊กซอว์ที่ได้:**
- **ตลาดกัญจน์ = ชั้น 6 ล้วน (<10ลบ)** = ชั้นที่ผู้รับเหมาเยอะสุด → แข่งดุ. "budget แบนราบ" ที่เจอ = เพราะอยู่ชั้นเดียว ไม่มีเส้นแบ่งให้ข้าม. **สอดคล้องทฤษฎีชั้น ไม่ขัด.**
- **เส้น 10 ล้าน เป็นเส้นแบ่งจริง:** ถนน <10ลบ ท้องถิ่น = ผู้เล่นประจำ 108 ราย ลด 28% → ถนน >10ลบ = ผู้เล่นประจำ ~45 ราย (14 เจ้าหลัก) ลด 0%. pool หด + ส่วนลดดิ่ง.
- **แต่ confound กับ DOH:** งานถนน >10ลบ ในพื้นที่ 90% เป็นกรมทางหลวง (480/531) → "ข้าม 10ลบ" = "กลายเป็น DOH" แยกไม่ได้ (งานท้องถิ่น >10ลบ มีแค่ ~51 งาน น้อยเกิน).
- **ชั้น = "สิทธิ์เข้า (eligibility)" ไม่ใช่ "ความดุการแข่ง (intensity)":** กรมทางหลวง ถนน <10ลบ (ชั้น6 value) มีผู้ชนะ 173 ราย (ไม่ใช่ pool เล็ก) แต่ลด 0% — pool ใกล้ท้องถิ่น แต่ระบอบ "ไม่กดราคา". ดังนั้น intensity = ระบอบตลาด ไม่ใช่จำนวน eligible.

**ข้อสรุปทฤษฎีชั้น:** ถูกในแง่ "เส้นแบ่งสิทธิ์ที่ value boundary (เด่นที่ 10ลบ)" — สำคัญถ้ากัญจน์ขยับไปงาน >10ลบ. แต่ในตลาดปัจจุบัน (<10ลบ ชั้น6) ไม่ช่วยทำนาย และ intensity ยังขับด้วยระบอบตลาด (A).

### 🐛 Data quality bug ที่เจอ (กัญจน์จับได้)
- **`winner_history.winner_tin` = ขยะ** — เก็บ *วันที่* (เช่น "8 ต.ค. 67") ไม่ใช่เลขนิติบุคคล. **ห้ามใช้ระบุตัวบริษัท** ต้องนับจาก `winner` (ชื่อ) แทน. **Followup:** เช็คว่า competitor_trend/cgd_intel ใช้ winner_tin ที่ไหนไหม → ถ้าใช้ = latent bug.
- **DB scope:** winner_history มีแค่ 2 จังหวัด (นครพนม 390K + บึงกาฬ 227K) — เลขทั้งหมดเป็นของพื้นที่กัญจน์อยู่แล้ว.
- **นับ pool ต้องระวัง:** "distinct winner 3 ปี" overcount (รวมขาจรชนะครั้งเดียว + ผู้รับเหมาข้ามจังหวัด เช่น เลย/มุกดาหาร/อุดร/ท่ามะกา). pool แข่งจริง = ดูผู้เล่นประจำ (≥3 งาน).
