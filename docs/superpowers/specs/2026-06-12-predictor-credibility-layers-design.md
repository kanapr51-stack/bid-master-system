## 1. ปัญหา (พิสูจน์แล้วด้วยเคสจริง)

งาน **69059227331** (ถนน คสล. ต.หนองเดิ่น อ.บุ่งคล้า บึงกาฬ · งบ 2,012,600):

| | ค่า |
|---|---|

| ราคาต่ำสุดจริง | **1,334,500** (ลด 33.7%, ผู้ชนะ หจก.โชคอนันต์77) |
| ผล | ❌ จริงสูงกว่ากรอบบน +8.6% — คาด "ลดลึกเกินจริง" |

เทียบ **69059132412** (อาคาร อบต.โพนทอง · scope อำเภอ n=3): คาด 4,268,250–4,577,250 · จริง 4,555,900 → ✅ ในกรอบ แม่น

### Root cause chain (พิสูจน์ครบทุกขั้น)

```
งานเป้าหมาย = ถนนคอนกรีต "สร้างใหม่"
  → predictor filter เข้ม: concrete + work_kind=new + contested floor 15 + ตำบล
  → 5 งานถนนหนองเดิ่นช่วง 3 ปีล่าสุด (2566-2568) โดนตัดทิ้งหมด
       (เป็น "เสริมผิว/ปรับปรุงผิว แอสฟัลต์" = คนละชนิดงาน)
  → recent window ว่าง → include_old fallback ย้อนไป 2562
  → เจอ หจก.มงคลธรรม 2 งาน (43%, 37.5%) — ตรง filter พอดี
  → ใช้คาด: n=2, บริษัทเดียว, เก่า 7 ปี, ยุคที่ตายไปแล้ว
```

**แก่น:** precedent ที่ใช้สะท้อน "ระบอบตลาดเมื่อ 7 ปีก่อน" (ยุคมงคลธรรมแข่งดุในหนองเดิ่น) ไม่ใช่วันนี้ — ขณะที่ข้อมูล **อำเภอบุ่งคล้าที่สดกว่า** (งานคอนกรีตใหม่ ล่าสุด median ~32%) ใกล้จริง 33.7% มาก แต่ถูกข้อมูลตำบลเก่าทับ

### 3 ความเข้าใจผิดที่ค่อยๆ ถูกแก้ระหว่าง diagnose
1. ไม่ใช่แค่ "ตำบลบาง n=2" — แต่เป็น "ไม่มี precedent ตรงชนิด+สดในพื้นที่ → บังคับ fallback ของเก่า"
2. "ปกติของบริษัท" ≠ "เป็นตัวแทนพื้นที่" (มงคลธรรม 40% ปกติ*สำหรับเขา* แต่ไม่ใช่เรตพื้นที่)
3. "ความสด" ขึ้นกับ "รัศมี" (มงคลธรรม = ผีในตำบลหนองเดิ่น แต่ยังสดในอำเภอบุ่งคล้า)

## 2. เป้าหมาย

ทำให้ price predictor **แม่นขึ้น + เสถียรขึ้น + ปรับตัวเร็วขึ้นแบบปลอดภัย** โดยไม่ over-react กับข้อมูลบาง/เบ้/เก่า

**Success:** รัน predictor กับเคส closed-loop ที่มี → 69059227331 ขยับเข้าหา ~1.33M (ใช้อำเภอสด) · 69059132412 ต้องไม่เพี้ยน (ยังแม่น)

**หลักการคุม scope (กฎโปรเจกต์):** build-from-evidence — เรามี evidence **เคสเดียว** ตอนนี้ ⇒ ทำของเล็กที่พิสูจน์ได้ก่อน, ของใหญ่รอ data foundation + เคสเพิ่ม (YAGNI)

## 3. สถาปัตยกรรม 4 Layer

แต่ละ layer แก้คนละ failure mode — ออกแบบให้ประกอบกันได้ (composable)

### Layer 1 — Scope Credibility (ตำบลบาง → เอนอำเภอ) ✅ *วิจัยแล้ว (2026-06-13)*
- **แก้:** ตำบลข้อมูลน้อย ไม่ควรทับอำเภอที่หนากว่า
- **สูตร final (validated):**
  ```
  Z = n / (n + 3)              n = #งานในตำบล (นับดิบ)
  เรตสนาม = Z·median(ตำบล) + (1−Z)·median(อำเภอ)
  ```
- **k=3 ยืนยัน 2 ทาง:** ทฤษฎี Bühlmann (k=EPV/VHM=3.2) + backtest 2,961 งาน (RMSE ดีสุด k=3–5) → ตรงกัน · curve แบน k=2–4 (robust)
- **นับ n ดิบ ไม่ใช่ effective-companies:** backtest พิสูจน์ eff ไม่ช่วยให้แม่นขึ้น → ใช้ n ดิบ (ง่ายกว่า)
- **การผูกขาด NOT อยู่ใน Z:** ข้อมูลยืนยัน — ลด Z เพราะผูกขาด = ไม่ช่วยทำนาย → ผูกขาดไปอยู่ที่ **C** (กัญจน์ argue ถูก)
- **blend ชนะ 2 ขั้ว:** pure-ตำบล RMSE 15.56 · blend k=3 = 15.49 · pure-อำเภอ 19.03 ❌ → ตำบลมีค่าแต่ห้ามเชื่อ 100%
- **หลักฐาน (หนองเดิ่น):** ตำบลเหลือแต่เจ้าใหญ่(แยกออก)→ว่าง → Z=0 → อำเภอล้วน 32% ≈ จริง 33.7% ✅
- รายละเอียด: `docs/research/2026-06-13-z-formula-credibility.md`

### Layer 2 — Bidder Consistency (vs ตัวเอง) — *แก้นิยาม (กัญจน์ review 2026-06-12)*
- **แก้:** bid ที่เป็น "one-off ของเจ้านั้น" (fluke/desperate) ไม่ควรเชื่อเท่าพฤติกรรมที่เขาทำสม่ำเสมอ
- **กลไก:** เทียบ bid กับ **ประวัติบริษัทนั้นเอง** (median + เทรนด์หลังจากนั้นเขายื่นอะไรอีก) — โดดจากสถิติตัวเอง → น้ำหนักน้อย · เป็นปกติของเขา → น้ำหนักมาก
- **semantics (สำคัญ):** "vs-self" ตอบคำถามจริง = *"ต้องทำยังไงถึงชนะเจ้านี้"* — เจ้าที่ลดดุเป็นนิสัย+สด+จริง **ต้องเชื่อ** (เตรียมสู้) ไม่ใช่ตัดทิ้งเพราะ "ห่างจากตลาด"
- **ทำไมไม่ใช่ vs-market:** มงคลธรรม 40% ปกติสำหรับเขา → vs-self เชื่อ (ถูก *ถ้า*สด+จริง). เคสหนองเดิ่น 40% ผิดเพราะ**เก่า (L3 จับ) + เจ้าเดียวครอง (L1 จับ)** — ไม่ใช่หน้าที่ L2
- **edge case เหลือ:** เจ้า **newcomer ไม่มีประวัติ** + bid โดด → vs-self ตัดสินไม่ได้ → ตรงนี้ vs-market ยังใช้เป็น **fallback** เฉพาะเจ้าไร้ประวัติ (ไม่ใช่ layer หลัก) — *open question*
- **caveat (predict min):** ระวังอย่าตัด "หางล่างก้าวร้าว" ที่จริง เพราะเราทำนาย **ราคาต่ำสุด** ไม่ใช่ค่ากลาง

### Layer 3 — Recency Credibility (ของสดหนัก / ผีจาง)
- **แก้:** ข้อมูลเก่าจากระบอบที่เปลี่ยนไปแล้ว ไม่ควรมีน้ำหนักเท่าของสด
- **กลไก:** ถ่วงน้ำหนักตามความสด (decay) — **ไม่ใช่ binary "เก่าเกิน=ตัด"** (consistent กับที่กัญจน์ชอบ soft กว่า hard)
  - ผีจริง (เช่น เค.อี.ซี. หาย 7 ปี) → น้ำหนักจางเองจนเกือบ 0
  - บริษัทที่ "จาง" ไม่ใช่ "หาย" (มงคลธรรม 40%→35%→25%) → ใช้พฤติกรรม**ล่าสุด** ไม่ใช่ของเก่า
- **scope ladder + cross-area (กัญจน์เพิ่ม):** ถ้า 3 ปีในตำบลไม่มีงานตรงชนิด → ขยาย: ตำบล→อำเภอ→จังหวัด→**ตำบลอื่นที่ระบอบตลาดคล้ายกัน** (งานประเภทเดียวกัน พื้นที่อื่นได้)
- **หลักการ:** **"ประเภทตรง + สด + พื้นที่กว้างกว่า" ดีกว่า "พื้นที่ตรง + เก่า"** (อำเภอสด 32% ชนะตำบลเก่า 40%) → ความสดสำคัญกว่าความใกล้เมื่อต้องเลือก
- **ปรับ:** ต้องนิยาม **รัศมี** ให้ชัด (ความสดในตำบล vs อำเภอ ตอบต่างกัน)
- **หลักฐาน:** include_old ดึง 2562 มาทับอำเภอสด = ต้นเหตุบั๊กตรงๆ

### Layer 4 — Competitor Entry / Behavior Model (ของใหญ่ · รวม L2)
- **แก้:** ราคาชนะสวิงตาม "ใครมายื่น" — เจ้าตลาดมา/ไม่มา เปลี่ยนเกมทั้งงาน
- **กลไก:** ดูข้อมูลจริง 1-2 ปีว่าใครเคยยื่นงานแบบนี้ในพื้นที่นี้ + **ความถี่การยื่น (ไม่ใช่แค่ชนะ → ต้องรวมผู้แพ้)** → P(เข้าร่วม) × เรตคาดของเขา (= L2 bidder profile)
  → **ราคาชนะ = ต่ำสุดในบรรดาคนที่น่าจะมา** → ออกเป็น **scenario** ("ถ้ามงคลธรรมเข้า ~1.2M / ถ้าไม่เข้า ~1.4M")
- **fallback ร่วมกับ L3 (กัญจน์):** ถ้า 1-2 ปีไม่มีการประมูลเลย → ขยายเวลา/พื้นที่ (กลไกเดียวกับ L3)
- **หลักฐาน:** มงคลธรรมไม่มางานนี้ (เป็นเทรนด์ ถอยจากหนองเดิ่นตั้งแต่ 2563) · ถ้ามาคาดเรตเขาจะกดราคาต่ำ
- **caveat:** วัด "เข้าร่วม/ความถี่" จาก *ชนะ* อย่างเดียวไม่ได้ (undercount คนยื่นแล้วแพ้) → **ต้องใช้ all-bidders**

### 🧩 โครงสร้างที่ตกผลึก (กัญจน์ review) — 2 กลุ่ม
แทนที่จะเป็น 4 layer แยก → จัด 2 กลุ่ม:

| กลุ่ม | คือ | ประกอบจาก |
|---|---|---|
| **A. น้ำหนักความเชื่อถือต่อ 1 ข้อมูล** | งานในอดีตแต่ละชิ้นเชื่อได้แค่ไหน | **L1** (scope/เจ้าเดียวครอง→Z) **× L3** (recency) |
| **B. โมเดลพฤติกรรม+การเข้าร่วมรายเจ้า** | เจ้านี้ปกติลดเท่าไหร่ (สด) + จะมายื่นไหม | **L2 + L4 ยุบรวม** (ต้องใช้ all-bidders) |

**ทำนาย = ต่ำสุดในบรรดาเจ้าที่ "น่าจะมายื่น" โดยใช้เรตปกติ(สด)ของแต่ละเจ้า ถ่วงด้วยความเชื่อถือกลุ่ม A**

> ⛔ **ตัดทิ้ง:** "Robust vs-market" เป็น layer แยก — ไม่จำเป็น (representativeness เกิดเองจาก L1+L3+L4) · เหลือเป็นแค่ fallback ของ L2 สำหรับเจ้าไร้ประวัติ

## 4. ฐานข้อมูลที่ขาด (foundation) — เก็บผู้ยื่นทุกราย

โผล่ซ้ำ 4 รอบในการ design — เป็นฐานของ **กลุ่ม B (L2+L4)**:

- ปัจจุบัน predictor ใช้ **ผู้ชนะอย่างเดียว** (cgd_winners/winner_history) — ทิ้งสัญญาณ ~80% (ราคาผู้แพ้)
- มีตาราง `bid_history` (Neon) แล้ว แต่เป็น **snapshot ครั้งเดียว 16 พ.ค. (300 งาน)** ไม่ต่อเนื่อง · 2 งานวันนี้ยังไม่เข้า
- **ต้องทำ:** ต่อ loop เก็บ `getProcureResult` ทุกรายลง bid_history ต่อเนื่อง (winner poller ดึงอยู่แล้ว แค่ persist เพิ่ม)
- **ได้:** 1 งาน = ~6 จุดแทน 1 → ตำบลหนาเร็ว ~6 เท่า + วัดอัตราเข้าร่วมจริง + โมเดลพฤติกรรมรายบริษัท
- **สำคัญ:** ต้องโมเดล **ราคาต่ำสุด (winning/min)** ไม่ใช่ค่าเฉลี่ยผู้ยื่น (เฉลี่ย 6 ราย = 1.74M สูงกว่าชนะจริง 1.33M)

## 7. ข้อควรระวัง (จากบทเรียนวันนี้)
- **soft > hard:** ทุก layer ใช้การถ่วงน้ำหนัก ไม่ใช่ cutoff แข็ง (กัญจน์ย้ำ 2 ครั้ง)
- **"เร็วขึ้น" บนข้อมูลบาง = ไม่เสถียร** — เร่งได้ปลอดภัยต่อเมื่อเพิ่มข้อมูล/เหตุการณ์ (all-bidders) ไม่ใช่เพิ่มน้ำหนักของใหม่บนข้อมูลเท่าเดิม
- **อย่า over-build บน n=1** — value = decision ดีขึ้น ไม่ใช่ coverage
- เกี่ยว: memory `project_scope_selection_bug`, `project_market_regime_pricing`, `project_competitor_trend`, `project_value_principle`

## ภาคผนวก A — Decision Flow (เมื่อมี 1 งานเข้ามา)

> 🔭 **เป้าหมายอนาคต:** render flowchart นี้บนหน้า `/audit` ต่อ 1 การทำนาย — ให้กัญจน์เห็นว่า "งานนี้เดินเส้นทางไหน · Z/C ออกมาเท่าไหร่ · ทับเจ้าใหญ่คนไหน" (ยังไม่ทำตอนนี้ — design future)

### A.1 นิยาม 2 ตัวแปรหลัก (แยกแกนกัน)

| ตัวแปร | คิดจาก | คุม | ขอบเขต |
|---|---|---|---|
| **Z** | #งาน + #บริษัทอิสระ **ในตำบล** | ผสม "เรตสนามพื้นฐาน" ตำบล↔อำเภอ กี่ % | **ตำบลเท่านั้น**; ถ้าอำเภอบางอีก recurse ต่อ (อำเภอ→จังหวัด) |
| **C** | ประวัติยื่นล่าสุด + ความถี่ในรัศมี + งบตรงไซซ์ | ทับ "เจ้าใหญ่" แต่ละราย ลงบนสนามไหม | คิด**ต่อเจ้าใหญ่แต่ละราย** (ทั้งจากตำบล+อำเภอ) |

**หลักกัน double-count:** แยก "เจ้าใหญ่" ออกจากข้อมูล**ก่อน**คำนวณเรตสนาม → แล้วทับกลับด้วย C (ไม่งั้นเจ้าใหญ่ที่อยู่ในข้อมูลตำบลถูกนับ 2 รอบ)

### A.3 จุดตัดสินใจ (แตก A/B/C ต่อ node)

| node | กรณี | ทำต่อ |
|---|---|---|
| **เฟส1 ข้อมูล** | ไม่มีตรงชนิดใน 3 ปี | ขยาย scope/เวลา (สด+กว้าง > เก่า+ตรง) |
| | ขยายสุดแล้วว่าง | ⛔ ตอบ "ข้อมูลไม่พอ" — ห้ามเดามั่ว |
| **เฟส3 Z** | A) สูง | เรตสนาม = ตำบล |
| | B) กลาง (~0.5) | เรตสนาม = ผสมตำบล+อำเภอ |
| | C) ต่ำ | เรตสนาม = เอนอำเภอ |
| **เฟส4 C (ต่อเจ้าใหญ่)** | A) ต่ำ (ถอยไป/ไม่เล่นไซซ์นี้) | ไม่ทับเจ้านี้ |
| | B) กลาง | เก็บเป็น scenario |
| | C) สูง (แอคทีฟ+ยื่นบ่อย) | ทับเรตเจ้านี้ |

### A.4 เคสตัวอย่าง: เจ้าใหญ่ 2 ราย + Z=0.5

ตั้งต้น: X=เจ้าตำบล (40%) · Y=เจ้าอำเภอ (38%) · เรตสนาม(หลังแยก X,Y, blend 50/50)=31%

```
• C_X สูง + C_Y สูง → ต้องสู้ 40% (X ลึกสุด)
• C_X ต่ำ + C_Y สูง → 38% (Y มา, X ไม่มา)
• ทั้งคู่ต่ำ          → 31% (เรตสนามล้วน)
• ก้ำกึ่ง            → ออก 2-3 scenario ให้คนตัดสิน
```
> **Z ไม่เกี่ยวกับเจ้าใหญ่** — Z แค่ปั้นเรตสนาม · เจ้าใหญ่ (กี่รายก็ตาม จากตำบลหรืออำเภอ) ประเมินทีละคนด้วย C แล้วทับ ใครลึกสุด+น่าจะมา = เพดานจริง

### A.5 เช็คแทรกทุกจุด (cross-cutting)
- **L2 bidder-consistency:** เวลาหยิบเรตบริษัทไหนมาใช้ (สนาม/เจ้าใหญ่) → bid ที่โดดจากนิสัยตัวเอง (one-off) ลดน้ำหนัก
- **L3 recency:** ทุกข้อมูลถ่วงตามความสด — ของเก่าจางเอง
- **newcomer ไร้ประวัติ + bid โดด:** C/L2 ตัดสินไม่ได้ → น้ำหนักกลางๆ + ป้ายเตือน (vs-market fallback)
